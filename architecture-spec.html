A001 · Aprobada

Transportes interoperables.

Esta decisión establece que la red debe conservar todas sus garantías esenciales aunque el único canal disponible sea Bluetooth Low Energy. BLE advertisements descubre candidatos, GATT sostiene control y transferencia degradada, L2CAP se utiliza cuando la combinación de equipos lo demuestra interoperable y Wi‑Fi Aware acelera cargas mayores sin convertirse en dependencia. La identidad del peer permanece separada de direcciones MAC, UUID periféricos o IP. En vehículos, donde orientación, metal, parabrisas e interferencia cambian constantemente, el engine mide progreso real y puede migrar el tráfico sin reiniciar la sesión ni el objeto.

Beacon lógico

Incluye protocol family, wire major, discovery alias, time slot, capability hint y autenticador truncado. Nunca incluye member ID, nombre o contenido.

Role arbitration

Un orden determinista derivado de aliases decide quién inicia central/client para evitar conexiones duplicadas. Una colisión se resuelve sin crear dos peers.

Link correlation

GATT, L2CAP y Wi‑Fi se asocian al mismo peer solo después del handshake. MAC, peripheral UUID o IP nunca son identidad.

Capability report

MTU, write mode, channels, throughput observado, costo de setup, disponibilidad y errores se reportan como hechos versionados.

Simultaneidad

BLE control permanece disponible durante Wi‑Fi cuando la plataforma lo permita. El scheduler usa un primario de datos y standby caliente.

Unsupported

Un transporte ausente degrada capacidad, no invalida membresía. El SDK diferencia unsupported, disabled, unauthorized y temporarily unavailable.

Control de conexión

Un peer, varios endpoints.

Endpoints nativos son efímeros. Tras autenticar, se adjuntan a PeerId; al desaparecer se invalidan sin tocar identidad ni objetos.

candidate_key = (adapter_id, opaque_endpoint, discovery_slot)
if simultaneous_dial:
    initiator = min(local_rotating_alias, remote_rotating_alias)
if authenticated_peer_already_has_equivalent_link:
    keep link with best negotiated tuple; close duplicate with reason DUPLICATE_LINK
on endpoint_change:
    preserve PeerSession; recreate TransportLink; resume from committed chunks

Scan/advertise cadence

Policy cambia intervalos por STARTING, ACTIVE, ISOLATED y RECOVERING. El core solicita intención; el adapter reporta lo que el OS realmente permitió.

Connection budget

Slots se asignan a peers autenticados con diversidad y backlog. Discovery candidates no pueden agotar conexiones o memoria.

MTU change

El adapter anuncia máximo actual. Framing fragmenta sin alterar chunk lógico; bajar MTU no invalida object manifest.

Wi‑Fi upgrade

Se ofrece sobre canal autenticado, se liga a session/peer mediante token efímero y solo recibe datos después de confirmar binding.

Gate A001: matriz iOS↔Android en ambos roles, GATT sostenido, spike L2CAP, Wi‑Fi Aware cuando exista y failback sin reiniciar objetos. Campaña física separa modelo de teléfono, OS, vehículo, posición y dirección del enlace.

A002 · Aprobada

Identidad y sesión segura.

Esta decisión convierte el grupo en una comunidad criptográfica y no en un conjunto de radios cercanos. Cada instalación genera claves propias, la autoridad del grupo emite certificados de membresía y los anuncios utilizan aliases rotativos para reducir seguimiento. Noise XX protege el primer encuentro autorizado y Noise IK reduce fricción al reencontrar peers conocidos, siempre con claves efímeras nuevas. La separación entre identidad, discovery, sesión, contenido y epoch limita el impacto de una filtración. Ningún nombre, proximidad física o conexión previa sustituye la validación de certificado, transcript, vigencia, epoch y anti-replay.

MembershipCertificate {
  certificate_id, group_id, member_id, peer_id,
  identity_signing_public_key, agreement_public_key,
  role, capability_constraints, valid_from, valid_until,
  issued_epoch, serial, authority_key_id, authority_signature
}

Autoridad

El grupo posee una raíz de autorización. Emitir, renovar o revocar membresía exige una operación firmada y monotónica dentro del epoch.

Instalación

Cada instalación genera Ed25519/X25519. Cambiar teléfono crea PeerId nuevo; una identidad de usuario puede autorizarlo mediante certificado nuevo.

Invitación

La invitación transporta group ID, autoridad, secreto/bootstrap de uso limitado, vigencia y parámetros. Se presenta por QR/enlace local y se consume una sola vez según policy.

Discovery alias

Alias derivado con HKDF desde secreto de discovery + time slot + contexto. Se aceptan ventanas adyacentes para skew; rotar no cambia PeerId.

Noise XX

Primer encuentro autorizado oculta/valida identidades progresivamente. Certificados, group ID, epoch y capabilities quedan ligados al transcript.

Noise IK

Reencuentro usa static keys conocidas para reducir round trips. Siempre produce traffic keys nuevas y packet space nuevo.

Key separation

Labels de KDF separan discovery, handshake, link traffic, object content, receipts y DB. Una clave nunca se reutiliza entre propósitos.

Rechazo

Certificado inválido, epoch incompatible, replay, firma incorrecta o transcript distinto cierra la sesión y genera reason code sin revelar detalles al atacante.

Replay y rotación

Cada capa tiene su ventana.

Un replay puede ser válido en una capa y duplicado en otra; por eso se separan handshake nonce, packet number, object ID e idempotency key.

Handshake replay

Ephemeral keys, transcript y nonces impiden reutilizar un handshake capturado como sesión nueva.

Packet replay

Sliding range por dirección descarta packet duplicado antes de ejecutar efectos.

Object replay

ObjectId + origin sequence deduplican incluso si llega por peers y transportes distintos.

Epoch overlap

Ventana limitada permite terminar objetos ya creados; objetos nuevos usan exclusivamente current epoch.

Clock failure

Si wall clock es dudoso, no se inventa validez. Se conserva objeto en cuarentena y se solicita reconciliación segura.

Device replacement

Un teléfono nuevo requiere certificado nuevo. Copiar DB sin claves del SecureKeyPort no clona identidad operativa.

Cierre A010: la suite exacta, HPKE por destinatario, revocación offline, recuperación de autoridad, crypto policy y assurance quedan definidas normativamente en A010.

A003 · Aprobada

Wire protocol.

Esta decisión define exactamente qué significa recibir, persistir, custodiar y entregar información. Un LinkPacket pertenece a una conexión concreta y puede confirmarse rápidamente; un MeshObject es inmutable, firmado, cifrado y capaz de sobrevivir transportes, saltos y reinicios. CBOR determinístico y CDDL producen representaciones canónicas verificables entre plataformas. Packet numbers, ACK ranges y credits gobiernan el enlace, mientras chunks, manifests y receipts gobiernan progreso durable. El parser aplica límites antes de reservar memoria y conserva bytes firmados originales, de modo que un relay pueda transportar campos o payloads futuros sin interpretarlos ni invalidarlos.

; CDDL conceptual: los nombres definitivos vivirán en protocol/*.cddl
link-packet = {
  0: uint,              ; wire version
  1: uint,              ; packet number < 2^62
  2: uint,              ; flags / packet type
  ? 3: [* ack-range],
  ? 4: uint,            ; receive credit
  ? 5: bstr             ; encrypted frame payload
}
mesh-object = {
  0: uint, 1: bstr, 2: bstr, 3: uint, ; version/id/origin/sequence
  4: audience, 5: uint, 6: uint,       ; target/epoch/priority
  7: uint, 8: uint, 9: tstr, 10: uint, ; lifetime/hops/namespace/schema
  11: bstr, 12: bstr, 13: bstr         ; manifest/ciphertext/signature
}

Canonical CBOR

Shortest encoding, deterministic map ordering, no indefinite lengths, duplicate keys rejected y límites de nesting/string/array.

Incremental parser

Framing consume bytes parciales sin copiar todo. Longitud física se valida antes de allocation y cada tick tiene CPU budget.

Packet space

Monotónico por sesión/dirección; 62 bits. Rekey antes del límite. Replay window acotada registra ranges recientes.

ACK ranges

Confirman packets del link actual. Ranges se compactan y limitan; ACK inválido nunca libera chunks durables.

Credits

Receptor anuncia bytes/frames aceptables. El emisor no excede inflight; writable nativo no reemplaza flow control lógico.

Chunks

Baseline 1 KiB lógico, negociable. Manifest fija count, tamaños y hashes; último chunk puede ser menor.

Canonical relay

Un relay conserva bytes firmados originales. Unknown fields y payloads opacos no se decodifican/reconstruyen.

Receipts

Receipt incluye object ID, etapa, actor, HLC, epoch y firma. LINK_ACK nunca se promueve a receipt durable.

Parser defense

Overlong varints, CBOR no canónico, depth, count, integer overflow, decompression bombs y trailing bytes producen rechazo.

A004 · Aprobada

Replicación y custodia.

Esta decisión permite que el grupo continúe funcionando cuando la cadena de vehículos se corta o cambia de orden. Los peers intercambian inventarios compactos, solicitan únicamente objetos y chunks faltantes y aceptan custodia solo después de verificar un commit durable. El origen conserva su copia; la transferencia no equivale a delegar ciegamente responsabilidad. Secuencias por origen, rangos ausentes, bitmaps parciales, audience epochs y receipts permiten que subgrupos separados converjan al reencontrarse. Lifetime, hop budget, presión de almacenamiento y utilidad de cobertura evitan flooding, loops y acumulación ilimitada.

INVENTORYContiguous + gaps
DIFFNeed por audiencia
WANTObjetos/chunks
TRANSFERPlan acotado
COMMIT/CUSTODYProgreso durable

Resumen por origen

highest_contiguous + missing ranges describe conocimiento sin Bloom false-positive. Inventarios grandes se paginan y llevan cursor.

Partial bitmap

Por objeto, un bitmap/RLE indica chunks committed. WANT solicita ranges exactos y se invalida si manifest no coincide.

Audience filter

Antes de pedir, se verifica target set, epoch, hop budget, lifetime, local policy y si el peer aporta cobertura/custodia útil.

Shared custody

El origen no borra al transferir. Se mantienen copias hasta que contrato, receipts y retention permitan compaction.

Partition merge

Subgrupos avanzan origin sequences independientes. Al reconectar, missing ranges y object IDs fusionan sin last-write-wins destructivo.

Late arrivals

Un hueco no bloquea mensajes posteriores. Al llegar tarde, HLC y causal metadata opcional permiten inserción determinista.

Loop prevention

Object ID dedupe, previous-hop hints, hop budget y custody history evitan loops; no se confía solo en TTL.

Backpressure

Inventory/WANT respetan presión del store y scheduler. Un receptor puede reducir credits sin perder membresía.

Planificación de réplica

Necesidad antes que oportunidad.

El planner calcula candidatos por objeto y después aplica byte budget; no recorre el store enviando por orden de inserción.

for object in eligible_objects(peer, audience, epoch, lifetime):
    need = peer_inventory.missing(object.origin, object.sequence, object.id)
    gain = coverage_gain(peer, object.targets) + custody_gap(object)
    cost = remaining_bytes(object, peer) / predicted_goodput(peer)
    risk = congestion(peer) + duplicate_risk(peer, object)
    rank = priority(object) + age_boost(object) + gain - cost - risk
select rank-descending while byte_budget and peer credits remain

Compaction segura

Borrar requiere evidencia.

El storage manager distingue payload bytes, metadata de entrega y evidencia anti-replay.

Payload eligible

Contrato satisfecho o lifetime vencido, sin custody obligation y retention cumplida.

Metadata retained

ObjectId, origin sequence y receipt digest permanecen durante dedupe horizon.

Never automatic

Pressure no elimina identidad, certificados activos, operations sin final o única copia bajo custodia.

Convergencia: se promete bajo ruta temporal suficiente, peers autorizados, capacidad y lifetime vigente. No se promete entrega cuando ningún camino físico aparece.

A005 · Aprobada

Core modular reutilizable.

Esta decisión impide que Mesh Lab se convierta en una implementación desechable o que iOS y Android desarrollen protocolos parecidos pero incompatibles. Rust contiene tipos, máquinas de estado, wire, seguridad, replicación, scheduling, scoring y simulación bajo un reactor determinista. Swift y Kotlin alojan ese runtime y traducen APIs de radio, lifecycle y almacenamiento seguro; Flutter consume una fachada tipada y nunca transporta frames internos. Ports estrechos hacen sustituibles transporte, store, reloj, random, claves y telemetría. Namespaces y policies permiten reutilizar la infraestructura en Convoy u otras aplicaciones sin forkar el núcleo.

Rust core

Tipos, codec, crypto orchestration, links, objects, replication, routing, scheduler, store contract, reducer y simulator.

Native hosts

Swift/Kotlin controlan lifecycle, permisos, BLE, Wi‑Fi, secure keys, threads y packaging sin duplicar semántica.

Flutter facade

Pigeon transporta comandos, snapshots y eventos agregados. Frames y secretos nunca atraviesan Dart.

Ports

Transport, ObjectStore, SecureKeyStore, Clock, RandomSource y TelemetrySink hacen sustituibles los bordes.

Extension registry

Apps registran namespace, schema, policies, codecs y handlers. Unknown payloads siguen siendo relayables.

No globals

MeshRuntime puede alojar sesiones aisladas; Mesh Lab crea una. Tests crean múltiples runtimes sin estado compartido oculto.

A006 · Aprobada

Scoring y failover.

Esta decisión transforma señales ruidosas de radio en cambios de canal controlados. El sistema distingue seleccionar vecinos, seleccionar transporte por peer y seleccionar relay por objeto, porque cada problema optimiza una cosa diferente. Delivery ratio, goodput, RTT, variación, estabilidad, progreso, setup y tendencia RSSI alimentan ventanas rápidas y lentas; RSSI nunca se interpreta como metros. La elección de transporte usa tiempo esperado de finalización, no una preferencia fija por Wi‑Fi. Hysteresis, healthy dwell, hold-down, cooldown y make-before-break evitan oscilación, mientras condiciones de hard fail permiten reaccionar sin esperar promedios.

link_health = w1*delivery_ratio + w2*goodput + w3*rtt + w4*stability
              - w5*loss - w6*progress_age - w7*setup_cost
eta = setup_remaining + pending_bytes / effective_goodput + retransmission_risk
neighbor_score = link_health + coverage_diversity + custody_reliability - congestion
forward_score = link_health + audience_need + coverage_gain + custody_history - duplicate_risk

Profiles

CONTROL prioriza confiabilidad/latencia; INTERACTIVE_SMALL latencia/jitter; BULK goodput/estabilidad. Pesos son policy versionada.

Thresholds

Healthy ≥70, usable 50–69, degraded <50. Fast EWMA ≈2 s; slow ≈10 s.

Soft failover

Candidato saludable durante 2 s, ETA 25% mejor, make-before-break y hold-down 5 s.

Hard fail

Adapter error, invalid crypto, peer lost, 3 RTO o 2.5 s sin progreso. Cambio inmediato si existe candidato.

Cooldown

2 s, 5 s, 10 s máximo por fallos repetidos; reset tras 30 s estable. Reason code acompaña cada transición.

Neighbors

Objetivo 3 autenticados, mínimo 2 si existen. Se busca diversidad de cobertura, no tres radios hacia el mismo sector.

Relay stagger

Mejor peer inmediato; segundo ≈150 ms sin progreso durable. Critical policy puede saltar stagger con cuota.

No striping

Un objeto no se reparte simultáneamente entre BLE/Wi‑Fi por defecto. Resume cambia transporte desde bitmap committed.

Anti-flap

Hysteresis, hold-down, slow score y minimum dwell separan recuperación real de ruido momentáneo.

Normalización

Unidades distintas, escala comparable.

Cada señal produce 0–100 mediante curvas acotadas. Missing data reduce confidence; nunca se rellena con un valor favorable.

Ejemplo

Wi‑Fi no siempre gana.

Un control pequeño favorece BLE inmediato; un clip favorece Wi‑Fi solo si setup y riesgo dejan margen suficiente.

BLE:  setup=.05s + 12KiB/8KiBps + risk=.30s   => ETA 1.85s
WiFi: setup=1.20s + 12KiB/250KiBps + risk=.05s => ETA 1.30s
improvement=29.7% // supera 25%, pero aún exige 2s healthy
decision: mantener BLE hasta cumplir estabilidad; luego make-before-break

A007 · Aprobada

Modelo de comunicación.

Esta decisión ofrece a las aplicaciones tres primitivas con semántica honesta: objetos durables para entrega asíncrona ASAP y store-carry-forward, datagramas efímeros para información momentánea y streams interactivos para flujo ordenado mientras exista una ruta. El direccionamiento captura un snapshot inmutable de destinatarios y epoch, y los contratos declaran exactamente cuándo una operación puede considerarse satisfecha. OriginSequence, HLC y causalidad opcional resuelven orden sin bloquear por huecos. Payloads opacos, namespaces y schemas mantienen extensibilidad. El audio de ocho segundos es una configuración de prueba, no una limitación del protocolo.

Datagram y stream

Menos garantía, reglas explícitas.

Datagram expiry

max_age se mide monotónicamente; vencido se elimina y nunca entra al backlog durable.

Datagram relay

Relay budget, nonce dedupe y audience limitan propagación. No produce custody ni receipt durable.

Stream ordering

Sequence, receive window y credits por stream. Gaps esperan solo dentro del jitter budget.

Stream migration

Conserva stream ID si continuity token y sequence coinciden; exceder interruption budget cierra instancia.

Backpressure

Write reporta accepted/blocked bytes. La captura se adapta; el SDK no acumula audio ilimitado.

Fallback

Cerrar stream y crear durable object produce operation ID nuevo y resultado independiente.

SDK y lifecycle móvil.

Esta decisión define cómo una app controla una infraestructura compleja sin conocer detalles de Bluetooth, Wi‑Fi, threads o almacenamiento. La API inspecciona capacidades antes de pedir permisos, expresa comandos mediante operation IDs idempotentes y entrega snapshot más stream secuenciado para no perder eventos. ACTIVE, DEGRADED, ISOLATED, SUSPENDED y RECOVERING reemplazan el booleano conectado. Swift y Kotlin poseen runtime y adapters; Dart observa estados agregados. Ante background, cierre o reinicio, el store y los contratos durables se recuperan, pero las conexiones y claves efímeras se autentican nuevamente porque ningún sistema operativo garantiza radio continuo.

Session states

IDLE, PREPARING, STARTING, ACTIVE, DEGRADED, ISOLATED, SUSPENDING, SUSPENDED, RECOVERING y STOPPING.

Snapshot + cursor

Snapshot y cursor se crean atómicamente; todo evento posterior posee sequence mayor. Resubscribe detecta gaps.

Permissions

Inspect no solicita. Request ocurre con intención concreta y desde UI elegible. Denied no entra en loop.

iOS lifecycle

Swift actor, CoreBluetooth restoration best-effort, scene callbacks, Keychain y reconsulta del estado real al volver.

Android lifecycle

Kotlin service, foreground connectedDevice cuando corresponda, notification visible y restart policy explícita.

Flutter

Pigeon tipado para comandos/eventos agregados. Isolate UI no aloja engine y hot restart de Dart no destruye store.

Shutdown

DRAIN termina control/checkpoints; PERSIST detiene radios conservando outbox. Force kill se recupera desde WAL.

Errors

Código estable, scope, retry directive, reason y diagnostic ID. Native errors se mapean; no atraviesan crudos.

Threading

Callbacks nativos se copian a mailbox acotado. Ningún callback ejecuta reducer en la cola del framework.

A009 · Aprobada

Observabilidad y validación.

Esta decisión hace que la confiabilidad sea demostrable y que cada fallo pueda reconstruirse sin capturar conversaciones ni debilitar la seguridad. Un flight recorder local y cifrado registra hechos secuenciados del protocolo, mediciones normalizadas y reason codes estables; varios dispositivos pueden exportar bundles explícitamente y sus trazas se fusionan aun cuando sus relojes civiles difieran. El mismo Rust Engine se ejecuta en un simulador determinista con reloj virtual, random sembrado y ports falsos, donde se inyectan pérdidas, particiones, movimiento, crashes, presión de almacenamiento y peers hostiles. Invariantes ejecutables, pruebas de conformidad y campañas físicas mixtas convierten el diseño en evidencia reproducible. Los SLO se evalúan bajo condiciones declaradas de ruta, capacidad, autorización y lifetime: nunca se ocultan fallos excluyendo casos después de observar el resultado.

Storage

Ring buffer cifrado por sesión con cuotas separadas para eventos y counters. Escritura append-only por segmentos y recuperación tolerante al último segmento incompleto.

Failure window

Eventos agregados normalmente; al detectar degradación conserva una ventana detallada previa/posterior sin habilitar payload capture.

Overflow

Se descartan primero eventos debug de alta frecuencia. Un contador por clase registra la pérdida; nunca se bloquea el reactor por telemetría.

Export

Bundle creado solo por acción explícita, manifest firmado, checksums por archivo y resumen visible de categorías incluidas.

Retention

TTL y cuota configurables. Borrar una sesión elimina segmentos y clave envolvente; no depende de sobrescribir sectores flash.

Modelo

Traces, metrics y events siguen semántica compatible con OpenTelemetry, sin introducir su SDK en el hot path.

Clock mapping

Cada handshake y ACK aporta pares de observaciones. El analizador estima offset e incertidumbre; no altera timestamps originales.

Causal edges

Packet number, object alias, receipt digest, HLC y operation ID unen eventos send/receive/commit entre bundles.

Conflicts

Orden total solo cuando existe evidencia. Eventos concurrentes se muestran como banda de incertidumbre, no con precisión inventada.

Integrity

Manifest, rangos de sequence y segment hashes detectan edición, truncamiento y gaps; el análisis conserva esas advertencias.

A010 · Aprobada

Hardening y certificación.

Esta decisión convierte los mecanismos criptográficos en una política operacional completa y verificable. Define algoritmos y contextos exactos, admisión de un uso, cifrado E2E independiente de los enlaces, rotación de epochs, revocación, recuperación de autoridad y protección local de claves. También delimita amenazas que el sistema sí puede mitigar y aquellas que ningún protocolo puede resolver, como jamming o un endpoint ya comprometido. El comportamiento es fail-closed: una incompatibilidad, downgrade, certificado inválido, replay o error de almacenamiento jamás habilita plaintext ni confianza reducida. Auditoría, fuzzing, supply-chain controls y pentest dejan de ser tareas opcionales y se convierten en condiciones formales del go/no-go.

Un único perfil interoperable.

Los identificadores de suite viajan autenticados y todo uso de KDF incluye protocol family, versión, grupo, epoch, propósito y dirección. No existe negociación hacia primitivas no listadas.

Content key

256 bits aleatorios exclusivos por objeto. Nunca se deriva directamente de identidad, grupo o payload.

Chunk nonce

Base nonce exclusiva más índice validado sin overflow. Retry retransmite el mismo ciphertext; no vuelve a cifrar con nonce reutilizado.

Recipient wrap

Solo miembros del snapshot reciben wrap. El delivery key ID debe pertenecer al certificado y epoch.

Relay

Valida forma, firma, digest, lifetime y policy; no posee content key si no es destinatario.

Unknown payload

Permanece ciphertext opaco y firmado; forwarding no requiere descifrar ni recodificar.

Erasure

Eliminar content key o wrapping key hace inaccesible la copia local; no promete borrar copias legítimamente exportadas.

Límite explícito: revocar protege objetos y discovery futuros. No puede retirar contenido ya descifrado ni impedir que un destinatario autorizado conserve o reproduzca su copia.
Recuperación de autoridad

Quórum 2-de-3 sin criptografía threshold propia.

Tres guardianes previamente registrados conservan claves independientes. Dos firman exactamente el mismo statement canónico; no se reconstruye ni comparte la clave anterior.

AuthorityRecoveryStatement {
  group_id, previous_authority_id, new_authority_public_key,
  previous_epoch, new_epoch, recovery_counter,
  membership_digest, reason_code, expires_at
}

accept iff:
  distinct_valid_guardian_signatures >= 2
  && recovery_counter == last_counter + 1
  && previous_epoch == local_epoch
  && membership_digest matches authorized base
  && statement not expired

Normal rotation

La autoridad vigente firma su sucesora. Guardianes no intervienen y el recovery counter no cambia.

Emergency recovery

Dos guardianes crean nueva autoridad y epoch. Todos los links y delivery keys anteriores se invalidan.

Conflicting recovery

Mismo counter con statements distintos entra en quarantine y exige resolución explícita; no se elige por llegada.

Guardian revoked

Cambiar guardianes requiere autoridad vigente o recovery válido y se hace efectivo en un nuevo epoch.

Threat model

Alcance de la promesa.

Cubierto

Escucha pasiva, MITM, rogue nearby peer, replay, downgrade, invitación reutilizada, miembro revocado, manipulación, parser hostil, robo bloqueado y supply-chain detectable.

Mitigación parcial

Traffic analysis, denial-of-service, almacenamiento lleno y dispositivo perdido: aliases, cuotas, rate limits, backoff, revocación y recuperación reducen impacto.

No cubierto

RF jamming, OS comprometido, dispositivo rooteado/desbloqueado con claves activas, micrófono capturado o extracción por destinatario legítimo.

Respuesta

Peer/link quarantine, revoke, epoch transition, authority recovery, diagnostic evidence y release incident process según alcance.
